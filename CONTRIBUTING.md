# Contributing

This project is a public educational reference. Contributions are welcome when they improve accuracy, clarity, practical usefulness, accessibility or the evidence behind a claim.

## Before editing

Read the [source register](06-reference/sources-and-updates.md). For product capabilities, prioritise current official provider documentation. Record the date checked, distinguish API capabilities from application access, and state any plan or region limitations. Do not replace a documented procedure with an unverified claim because an interface looks different in your account.

## For a new lesson

Explain the job, the input source, setup, prompt or interface procedure, example, correction method, human review and permission boundary. Use authentic but nonconfidential screenshots only with appropriate rights, or create an original instructional diagram. Do not submit invented customer quotes, fabricated metrics or private client records.

## Visual standards

Keep figures accessible with useful alternative text. Prefer legible SVG diagrams and locally stored image assets. Check contrast, labels, mobile readability and relevance. Avoid decorative gradients when they obscure the message. Show before and after comparisons when they teach a specific repair.

## Pull request checks

1. Open the changed Markdown file in GitHub preview.
2. Test every relative asset and internal Markdown link.
3. Verify example calculations independently.
4. Mark hypothetical scenarios as hypothetical.
5. Check source URLs and disclosure obligations.
6. Describe what changed and why it improves the lesson.

Commercial interests or affiliate links should be disclosed. Please do not add undisclosed promotion or copied proprietary training material.
