# Maintaining a fast-changing public course

An educational repository covering current software is a living publication. A page may be accurate when written and misleading six months later because a provider renames a model, removes a feature, changes pricing or moves a menu. This page defines how to handle that honestly.

## Review schedule

Review high-change model and product claims monthly when maintaining the project actively. Review safety, platform disclosure and legal references before every significant release. Review screenshots after vendor interface changes. A date at the top of a page means it was reviewed on that date, not that it remains correct forever.

## Evidence standard

For every feature claim, prefer the product's documentation or release notes. Save the official URL and the date checked. Distinguish a model available by API from a consumer app capability. Mark features that depend on plan, region, account role or preview enrolment. Do not copy benchmark advertising as an independent performance finding.

## Change log entry

```text
Date:
File:
What changed:
Official source:
Account or product surface affected:
What remains uncertain:
Reviewer:
Broken links and image assets checked: yes/no
```

## Community corrections

A contributor should report a reproducible problem with the model or app version, original wording, official source and proposed correction. Editors should test the relevant workflow and preserve learner clarity. Avoid adding instructions for harmful impersonation, disclosure evasion, fabricated reviews or unapproved financial actions.
